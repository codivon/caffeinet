- **۲-۹:** صفحهٔ عمومی `/speed` + ویجت iframe (CSP `frame-ancestors`) + تست دانلود/آپلود/پینگ با JS خالص به endpoint باینری محلی + داشبورد «متوسط سرعت شعبه‌ها» در `/status`. توجه به پهنای‌باند/Entry Processes (هم‌نگرانی SSE ۵۹-c).
- **۲-۱۰:** HTTP client لاراول به API مدل زبانی (کلید در settings، الگوی sms.kavenegar) + context محدود از دادهٔ خود کاربر (بدون PII) + پاسخ غیر-stream (سازگارتر با LiteSpeed از SSE طولانی) + ذخیرهٔ پاسخ در `ticket_messages` با نوع `bot` + سقف روزانه + پاورقی «پاسخ ربات». فال‌بک بدون سرویس بیرونی: موتور قاعده‌محور FAQ (۱-۶).
- **۲-۱۱:** لایهٔ شرطی `operator.mobile` (UA/کوکی) با صف بزرگ پذیرش، دکمه‌های لمسی وضعیت و چت تمام‌صفحه (الگوی تیکت موبایل فاز ۴۵) — همان روت‌ها/داده، فقط Blade متمایز.
- **۲-۱۲:** فیلد اختیاری `scheduled_at` در ثبت سفارش (قبل از پرداخت) + وضعیت `scheduled` قبل از ورود به پخش + کرون دقیقه‌ای که سرِ موعد به `pending_payment/broadcasting` منتقل می‌کند + تقویم ماهانهٔ سادهٔ نوبت در پنل کافی‌نت (CSS خالص، بدون کتابخانهٔ تقویم).
- **۲-۱۳:** امتیاز از همان دادهٔ `DispatchStatsService` (پذیرش/رد/رأی/SLA رعایت‌شده) + بج و جدول رتبهٔ ماهانه در `/operator` و `/admin/operators` + بونوس دستی کیف پول اپراتور با تأیید ادمین (الگوی تسویهٔ دستی موجود).

**نکات فنی:**
- **۳-۱:** cache-first برای shell (کاتالوگ/آخرین وضعیت از API کش‌شده) + Background Sync API برای صف پیام/تأیید + صف محلی در `CN.api` با نشانگر «آفلاین — پس از اتصال». سقف cache ~۵۰MB.
- **۳-۲:** Leaflet vendored + کاشی OpenStreetMap (فقط تصویر کاشی بیرونی؛ فال‌بک لیست متنی) + صفحهٔ `/branches` + ادغام در `/status` — CSP باید دامنهٔ کاشی را مجاز کند.
- **۳-۳:** جدول `dispatch_rules` (شرط JSON: خدمت/ساعت/شعبه/سقف) + ارزیابی در `targetCoffeenets` قبل از امتیازدهی + UI فرم‌های شرطی سادهٔ Livewire (بدون درگ‌دراپ).
- **۳-۴:** جدول `events` سبک (view_service/start_form/submit/pay/…) با ثبت non-blocking از کوئیو + قیف/retention در `/admin/analytics` با Chart.js موجود. نوشتن batch برای MySQL اشتراکی.
- **۳-۵:** `Appearance::tokensFor` پالت هر پنل را می‌سازد؛ این آیتم = دامنهٔ فرعی + لوگو/نام سفارشی روی لایهٔ app (رزولوشن tenant از host + کش) + مانیفست اختصاصی. کوکی scope‌دار برای جدایی نشست.
- **۳-۶:** فرمان schedule روزانه که laravel.log را پارس و در `error_digest` (فایل/عنوان/تعداد/آخرین) بریزد + کارت «سلامت خطاها» در `/admin/health` — بدون سرویس بیرونی.
- **۳-۷:** Trusted Web Activity با `assetlinks.json` در public؛ APK یک‌بار با Android Studio خارج از ریپو ساخته می‌شود — وب هیچ تغییری جز assetlinks نمی‌خواهد.
- **۳-۸:** `services.city_overrides` (قیمت/وضعیت به‌ازای شهر) + انتخاب شهر در لندینگ (کوکی) + فیلتر کاتالوگ — multi-tenancy سبک داخلی؛ فقط بعد از ۲-۸ و با دادهٔ واقعی تقاضا.
- **۳-۹:** وضعیت `pending_approval` در state machine (کارمند درخواست → مدیر سازمان تایید) + سقف‌های سازمانی (reuse الگوی خانوادهٔ فاز ۵۳) + صفحهٔ فاکتورهای سازمان + خروجی حسابرسی CSV.
- **۳-۱۰:** شماره‌گذاری ترتیبی فاکتور + سری مالیاتی + PDF از موتور ۲-۶ + نگاشت `orders/service_costs` به ردیف‌ها + فیلد `economic_code` روی سازمان (جدولorganizations گسترش) + گزارش فروش دوره‌ای ادمین. اتصال مؤدیان فقط بعد از تعیین تکلیف مقررات.
- **۳-۱۱:** درایور کانال جدید در abstraction پیامک موجود (SmsManager → NotificationChannel) + درایور واتساپ API رسمی یا بات تلگرام (webhook سادهٔ POST بدون realtime) + قالب جدا از پیامک + سوییچ features. اگر سرویس بیرونی/تحریم ریسک بود، فقط تلگرام بات شخصی.
